================================================================================
PROJECT OVERVIEW
================================================================================

FindMyAisle is a Laravel 11 backend application that helps users navigate 
grocery stores by:
- Managing store floor plans from DXF CAD files
- Creating and managing shopping lists
- Calculating optimal navigation paths through stores
- Categorizing products by aisle location

Backend: Laravel 11 + MySQL + Sanctum Authentication
Current Frontend: Inertia.js + Vue 3 (to be replaced with Flutter)
Base URL: Your Laravel API (e.g., https://api.findmyaisle.com)

================================================================================
SECURITY & AUTHORIZATION
================================================================================

Laravel Policies
--------------------------------------------------------------------------------
- ShoppingListPolicy: Users can only view/edit/delete their own lists
- Automatically enforced on all shopping list endpoints
- Returns 403 Forbidden if user tries to access another user's list

Middleware
--------------------------------------------------------------------------------
- auth:sanctum - Requires valid bearer token
- admin - Requires is_admin = true on user

Validation Rules
--------------------------------------------------------------------------------
All create/update endpoints validate input:
- Shop: name required (max 255), description (max 1000), address (max 500)
- Category: name required + unique (max 255), color must be hex (#FFFFFF)
- Product: name required (max 255), category_id must exist, barcode unique
- ShoppingList: name required (max 255)
- ShoppingListItem: name required (max 255), quantity 1-999

COMPLEX FEATURES
================================================================================

1. Map Visualization
--------------------------------------------------------------------------------
Current Implementation: JavaScript (Konva.js canvas library)

map_data Structure:
{
  bounds: {
    minX: 0, minY: 0, maxX: 1000, maxY: 800,
    width: 1000, height: 800
  },
  entities: {
    lines: [{start: {x, y}, end: {x, y}, layer: "WALLS"}],
    polylines: [{points: [{x, y}, ...], layer: "WALLS", closed: true}],
    shelves: [
      {
        id: 0,
        type: "shelf",
        bounds: {minX, minY, maxX, maxY},
        lines: [...],
        polylines: [...]
      }
    ],
    startPoint: {x: 50, y: 50},  // Entrance
    endPoint: {x: 950, y: 50}    // Exit
  }
}

For Flutter:
- Option A: Use CustomPainter to draw lines/polylines
- Option B: Use flutter_map or similar
- Option C: Embed WebView showing the Vue map

2. Pathfinding Algorithm
--------------------------------------------------------------------------------
Current Implementation: JavaScript A* pathfinding

Logic:
1. Creates a grid overlay on the map (default 20px cells)
2. Marks obstacles (walls, shelves) as unwalkable
3. Calculates access points for each shelf (closest walkable point)
4. Uses A* algorithm to find optimal path
5. Applies TSP (Traveling Salesman) heuristic for multiple aisles

Key Calculations:
// Access points are calculated and stored in shelf_access_points
{
  "0": {  // Shelf ID
    "x": 125,
    "y": 450,
    "shelfId": 0,
    "position": "bottom-30"  // Which side + offset
  }
}

// Path calculation requires:
// - startPoint (entrance)
// - List of shelf IDs to visit
// - endPoint (exit)
// Returns: Array of {x, y} coordinates

For Flutter:
- Option A: Port A* algorithm to Dart
- Option B: Calculate paths server-side, return coordinates via API
- Option C: Use Dart pathfinding package (e.g., a_star_algorithm)

3. DXF File Processing
--------------------------------------------------------------------------------
Current Implementation: JavaScript library (dxf-parser)

Process:
1. Upload DXF file (CAD floor plan)
2. Parse entities (lines, polylines, circles)
3. Group connected shapes into shelves
4. Extract START/END navigation points from specific layers
5. Store as JSON in map_data

For Flutter:
- Admin feature only
- Can keep as web-only upload
- Or use multipart form upload from Flutter

SAMPLE FLUTTER API SERVICE
================================================================================

import 'package:dio/dio.dart';
import 'package:shared_preferences/shared_preferences.dart';

class ApiService {
  static const String baseUrl = 'https://yourapi.com';
  late Dio dio;
  
  ApiService() {
    dio = Dio(BaseOptions(
      baseUrl: baseUrl,
      connectTimeout: Duration(seconds: 5),
      receiveTimeout: Duration(seconds: 3),
    ));
    
    dio.interceptors.add(InterceptorsWrapper(
      onRequest: (options, handler) async {
        final token = await _getToken();
        if (token != null) {
          options.headers['Authorization'] = 'Bearer $token';
        }
        return handler.next(options);
      },
    ));
  }
  
  Future<String?> _getToken() async {
    final prefs = await SharedPreferences.getInstance();
    return prefs.getString('auth_token');
  }
  
  // Login
  Future<Map<String, dynamic>> login(String email, String password) async {
    final response = await dio.post('/login', data: {
      'email': email,
      'password': password,
    });
    return response.data;
  }
  
  // Get shopping lists
  Future<List<dynamic>> getShoppingLists() async {
    final response = await dio.get('/api/shopping-lists');
    return response.data;
  }
  
  // Search products
  Future<List<dynamic>> searchProducts(String query) async {
    final response = await dio.get('/api/products', queryParameters: {
      'search': query,
    });
    return response.data;
  }
  
  // Create shopping list
  Future<Map<String, dynamic>> createShoppingList(String name) async {
    final response = await dio.post('/api/shopping-lists', data: {
      'name': name,
    });
    return response.data;
  }
  
  // Add item to shopping list
  Future<Map<String, dynamic>> addItemToList(
    int listId, 
    String name, 
    int quantity,
    {int? productId}
  ) async {
    final response = await dio.post(
      '/api/shopping-lists/$listId/items',
      data: {
        'name': name,
        'quantity': quantity,
        if (productId != null) 'product_id': productId,
      },
    );
    return response.data;
  }
  
  // Update item
  Future<Map<String, dynamic>> updateItem(
    int listId,
    int itemId,
    {String? name, int? quantity, bool? checked}
  ) async {
    final response = await dio.put(
      '/api/shopping-lists/$listId/items/$itemId',
      data: {
        if (name != null) 'name': name,
        if (quantity != null) 'quantity': quantity,
        if (checked != null) 'checked': checked,
      },
    );
    return response.data;
  }
  
  // Delete item
  Future<void> deleteItem(int listId, int itemId) async {
    await dio.delete('/api/shopping-lists/$listId/items/$itemId');
  }
  
  // Get shops
  Future<List<dynamic>> getShops() async {
    final response = await dio.get('/api/shops');
    return response.data;
  }
  
  // Get shop details
  Future<Map<String, dynamic>> getShop(int shopId) async {
    final response = await dio.get('/api/shops/$shopId');
    return response.data;
  }
}

DIFFICULTY ASSESSMENT
================================================================================

Integration Difficulty: 6/10 (Moderately Difficult but Feasible)

Current State - Good News:
--------------------------------------------------------------------------------
✅ You already have a REST API (most routes in routes/api.php)
✅ Laravel Sanctum is set up for API authentication
✅ API endpoints are well-structured and use proper JSON responses
✅ Authentication, authorization policies, and Form Requests are in place

Current State - Challenges:
--------------------------------------------------------------------------------
❌ Inertia.js is tightly coupled to the Vue.js frontend (server-side rendering)
❌ Some routes use Inertia page rendering instead of API responses
⚠️ Sanctum is configured for SPA mode, needs adjustment for mobile

What Needs to Change:
--------------------------------------------------------------------------------

1. Authentication (Easy - 2 hours)
   - Sanctum already supports token-based auth for mobile
   - Need to add a token-based login endpoint
   - Flutter uses Authorization: Bearer {token} headers

2. API Completion (Medium - 8 hours)
   - Most endpoints exist, but some features only work via Inertia
   - Need to ensure all CRUD operations have API endpoints
   - Add proper API error responses (currently some return HTML)

3. File Handling (Medium - 4 hours)
   - DXF upload works but might need multipart/form-data handling
   - Image uploads if you add product images later

4. Complex Features (Hard - 16 hours)
   - Map rendering: The canvas-based map (Konva.js) won't work in Flutter
   - Need to either:
     * Rebuild map visualization in Flutter (using CustomPainter)
     * Use WebView to display the map (easier but less native)
   - Pathfinding: The JavaScript pathfinding logic needs to be:
     * Ported to Dart, OR
     * Run server-side and return path data via API

Recommended Approaches:
--------------------------------------------------------------------------------

Option 1: Hybrid (Easiest - 1 week)
// Use Flutter for lists, forms, authentication
// Use WebView for complex map visualization
WebView(
  initialUrl: 'https://yourapi.com/map-view/${shopId}',
  javascriptMode: JavascriptMode.unrestricted,
)

Option 2: Full Native (Best UX - 3-4 weeks)
- Rebuild map rendering in Flutter using CustomPainter
- Port pathfinding logic to Dart
- Completely native experience

Option 3: API-First Refactor (Most Flexible - 2-3 weeks)
- Move map processing and pathfinding to backend
- Return simplified data structures to Flutter
- Flutter just displays the results
